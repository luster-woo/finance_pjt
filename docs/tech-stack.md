# FinFit 기술 스택

## 백엔드

Django를 선택한 건 팀 내 Python 경험이 많기도 했지만, 이 프로젝트에서 특히 ORM이 빛을 발했습니다. FSS API 응답을 파싱해서 DB에 넣는 부분, 금융성향 검사 결과와 추천 내역을 연결하는 쿼리, 비슷한 성향 사용자 통계를 뽑는 집계 — 전부 SQL 없이 깔끔하게 처리했습니다. FastAPI도 검토했는데, 비동기 I/O 이점을 살리려면 외부 API 호출도 전부 `asyncio`로 바꿔야 해서 공수가 더 컸습니다. 이 규모에서 응답속도 차이도 비슷하였습니다. 

DRF는 클래스형 뷰 대신 `@api_view` 함수형 뷰를 주로 썼습니다. 추천 로직처럼 전처리가 복잡한 뷰는 클래스로 추상화하면 오히려 읽기 어려워져서, 의도를 그대로 드러내는 함수형을 사용하였습니다ㅣ. 

**인증**: SimpleJWT로 Access(2h) + Refresh(7d) 토큰 구조를 썼고, 로그아웃 시 Refresh 토큰을 블랙리스트에 올려서 실제 무효화가 됩니다. 세션 기반을 안 쓴 건 Vue 프론트와 origin이 다른 구조에서 쿠키 관리가 복잡해지기 때문입니다.

**스케줄러**: 뉴스 브리핑 자동 생성에 APScheduler를 썼습니다. Celery + Redis로 하면 더 견고하겠지만, 주 1회 브리핑 생성에 브로커를 별도로 띄우는 건 이 프로젝트에서 필요 이상이었습니다. APScheduler는 Django 프로세스 안에서 돌아서 설정이 간단하고, 포트폴리오 용도에선 충분합니다.

**DB**: SQLite3를 그대로 씁니다. 배포 환경 없이 로컬에서 돌리는 포트폴리오라 문제없고, `USE_TZ = True`로 설정해 모든 datetime을 Asia/Seoul 기준 timezone-aware로 관리합니다. 처음에 이 설정 없이 진행했다가 yfinance에서 받아온 날짜와 DB 저장값이 안 맞는 버그를 겪었습니다.

## 프론트엔드

Vue 3 Composition API를 선택했습니다. 금융성향 검사처럼 단계별 상태가 많은 페이지에서 Options API는 `data()` / `methods` / `computed`가 뿔뿔이 흩어지는 느낌인데, Composition API는 같은 기능의 로직을 `setup()` 안에 모아둘 수 있어서 훨씬 추적하기 편했습니다. React도 가능하지만 Vue의 단일 파일 컴포넌트(SFC)가 템플릿·스크립트·스타일을 한 파일에 담아서 협업할 때 파일 간 이동이 적었습니다. 카카오 지도 SDK처럼 전역 스크립트로 로드하는 외부 라이브러리를 템플릿에서 바로 쓸 때도 Vue가 더 자연스럽게 작동했습니다.

상태 관리는 Pinia입니다. Vuex는 mutations와 actions를 이중으로 작성해야 해서 반복 코드가 많았는데, Pinia는 `defineStore`에 state·getter·action을 한 번에 정의합니다. `useAuthStore`에서 로그인 상태, 토큰, 사용자 정보를 관리하고, localStorage 변경을 `auth-changed` 이벤트로 감지해서 탭 간 동기화도 처리했습니다.

차트는 Chart.js (`vue-chartjs` 래퍼)를 썼습니다. D3.js도 강력하지만 학습 비용이 크고, 이 프로젝트에서 필요한 건 라인 차트와 바 차트 정도였습니다. Chart.js로 주식 시세 라인 차트, 저축 플래너 누적 그래프, 마이페이지 금리 비교 바 차트를 구현했습니다.

빌드 도구는 Vite입니다. Webpack 대비 개발 서버 HMR이 눈에 띄게 빠르고, 환경변수(`.env`)와 경로 별칭(`@`)이 별도 설정 없이 바로 됩니다.

## 외부 서비스

**FSS Finlife API**는 금융감독원의 금융상품 공시 API입니다. 예금·적금 상품 전체 데이터를 여기서 가져옵니다. API를 직접 프론트에 연결하지 않고 백엔드에서 주기적으로 수집해 DB에 저장하는 방식을 택했는데, API 응답이 느리고 필터·정렬 같은 기능을 직접 지원하지 않아서입니다. DB에 넣고 나면 ORM으로 자유롭게 쿼리할 수 있습니다.

**yfinance**는 Yahoo Finance 비공식 Python 라이브러리입니다. 한국 주식 데이터(KOSPI는 `.KS`, KOSDAQ은 `.KQ` 티커)와 종목 관련 뉴스를 가져올 때 사용합니다. 비공식이라 스펙이 조용히 바뀌는 경우가 있고, 실제로 개발 중에 `ticker.news` 응답 구조가 한 번 달라져서 파싱 코드를 수정했습니다.

**SSAFY GMS API**는 OpenAI 호환 형식의 LLM API입니다. 금융상품·주식·카드 추천, 종목 뉴스 한국어 번역, 주간 브리핑 생성에 씁니다. OpenAI 호환 형식이라 `api_url`과 `api_key`만 바꾸면 다른 제공자로 교체됩니다. GMS 장애 대비 Gemini 1.5 Flash를 폴백으로 연결해뒀는데, 실제로 테스트 중에 한 번 GMS가 응답이 없어서 폴백이 동작했습니다.

**Kakao Maps + Kakao Mobility API**는 주변 은행 검색과 경로 안내에 씁니다. Google Maps와 비교했을 때 국내 지점 정보가 더 정확하고, 카카오 모빌리티가 대중교통 경로를 함께 제공합니다. 다만 Kakao REST API 키와 JavaScript 키가 별도로 필요해서 환경 설정이 조금 번거롭습니다.
